## Day 1（2026-08-28）：核心循环

### v0.0 规则内核（TDD 先行）

**做了**：board.js（棋盘/状态编码）、move.js（移动/班车/捎人）、goal.js（目标谓词）+ 8 个单元测试。

**测试暴露的第一个 bug**：初版 `slideTargets` 没有排除被移动车辆自身——自己挡自己，所有车辆都动不了。单元测试 6/8 失败暴露。
**修复**：占用网格计算排除自身（`gridWithout(level, s, excludeId)`）。

**测试暴露的第二个 bug**：出口定义在棋盘外（x=6），胜利判定 `carCells.some(c => c.x === exit.x)` 永远为 false。
**修复**：引入"道闸格"语义（`gateCell`）——出口相邻的棋盘内格。英雄车占据道闸格即逻辑胜利，滑出棋盘是纯演出。

### v0.0 求解器（双算法交叉验证）

**做了**：BFS 求解器（可解性/par/路径）+ 每车必要性 + 解路径窄度 + 独立 IDDFS 交叉验证。

**迭代 1：交叉验证测试超时**。初版随机测试对不可解关也跑完整 IDDFS（指数爆炸）+ `JSON.stringify` 做状态键（慢）。修复：IDDFS 只验证最优性（BFS 完备性由图搜索数学保证），键改为手工拼接，深关抽样跳过。150 关交叉验证 4.3s 全过。

**迭代 2：必要性判据语义错误**。初版"删车后仍可解=非必要"恒真（删车只会释放空间）。修复为"删车后 par 不降=装饰车"——语义正确的难度贡献判据。

**迭代 3：窄度定义重构**。初版"≤par+2 的解路径数"含混。重构为"恰为 par 的最优解路径数"——同档内越少越难，手工关验证（单车关=1，双逃逸关=3）。

**迭代 4：手工测试关 B 设计错误**。我手推 par=2 的关卡实际不可解（横车挡在出口行且无车能挪开它）——求解器是对的，人错了。换成双竖挡关（手推 par=3 验证通过）。教训：**手摆关卡不可信，这正是求解器管线存在的理由**。

## v0.3 50 关生产管线 + 元系统（Day 2-3）

**关卡生成器三轮迭代**（每轮有数据）：
1. v1 均匀随机布局 → 探针发现 par 中位数=1（英雄车常可直达出口，无阻挡结构），不可用
2. v2 反向打乱法（从 solved 态逆推）+ par 带拒绝 → 接受率 0（打乱不产生深度纠缠；7×7 状态空间爆炸，10 分钟超时）
3. v3 **英雄车最左出发 + 出口行显式竖挡（难度骨架）+ 密度分章** → 梯度成立：ch1 par 1-3 → ch5 par 3-7，validate 全过

**关键砍刀（按砍序执行）**：班车机制在生成器接受率仅 1/201（班车每步推进破坏可解性），且列砍序首位 → **砍掉班车**；7×7 状态空间爆炸 → **砍掉 7×7**。难度改由"密度 + 墙 + 按序接送"提供。保留机制阶梯：基础滑块 → 捎人 → 捎人+墙 → 按序双乘客+墙。

**难度工程落地**：
- 50 关 100% 求解器验证（可解 + par 一致），validate.js 作 CI 门
- 各章 par 范围：ch1[1,3] ch2[2,5] ch3[2,6] ch4[5,7] ch5[3,7]，中位数单调不降（validate 强制校验）
- 波浪排序：章内"3 升 1 缓 + 章末峰值"

**元系统**：星级存档、连胜计数、每日挑战（10 关池按日期取模）、内置 AI 提示（每关 3 次，求解器同源给最优第一步）

**手感**：WebAudio 合成音效（移动/接人/道闸/通关）、通关红车冲出出口动画

**验证**：16 单测 + validate(50+10) + Python 独立求解器 50 关端到端自动通关 ALL PASS + 零页面错误

## v0.4 真人试玩反馈驱动（G1/G2 门）

**用户试玩原话**："确实很解压，音效也很好，手感也还行。问题是不是难度太低了一点点？而且我们的车只能横着移动的话，接人也只能在那几个固定位置，也没有加多少难度。何况滑块还能把人盖住，这个要改，人也算滑块的障碍物。"

**根因**：乘客格此前不参与占位网格，车辆可滑过乘客（"盖住"），乘客游离于疏通结构之外，捎人只制造绕路、不制造难度。

**改动**：
1. **乘客=障碍物**：未接乘客占格，任何车不可滑过；接走后格子开放。捎人从"绕路"升级为"开闸+清障"双重收益，乘客位置（决定封哪一列）与接人时机成为策略本身——把"接人位置固定"的缺点变成特点。规则内核与求解器同源，改一处全管线自动重验。
2. **提难度**：各章出口行竖挡骨架 +1（ch1 block2 → ch5 block4）。

**结果**：难度曲线 ch1[2,3] → ch2[2,6] → ch3[3,6] → ch4[3,9] → ch5[4,10]，章末峰值 10，递进成立。
**验证**：17 单测（新增"乘客是障碍"测试）+ validate(60) + 50 关自动通关 ALL PASS + 零页面错误。

## v0.5 玩家共创：师傅掉头 + 每章大关（用户建议驱动）

**用户试玩原话**："难度还是很低。车只能横着移动的话接人只能在那几个固定位置。能不能做那种车可以原地转向，2x1 在 2x2 空间转成 1x2？能不能每 10 关做一个大关，地图放大几倍，车也变长？"

**改动 1｜师傅掉头（转向机制）**：
- 只有英雄车（师傅）能 90° 原地掉头（len2，需 2×2 空间，绕任一端点摆向空位），违停死车只会滑——贴合主题且控制求解分支。
- 一举解决两个问题：① 红车可纵向机动 → 乘客全图可放（"接人位置固定"的缺点消失）；② 解法空间变深 → 难度上限大幅抬高（ch4/ch5 峰值 17-24）。
- 朝向成为状态的一部分：stateKey/渲染/输入/求解器/Python 验证端全链路重构，19 单测护航。
- 交互：垂直于车身方向拖动 = 掉头（顺向拖 = 滑动），符合直觉。

**改动 2｜每章大关**：每章第 10 关 = 7×7 放大地图 + 加长车（len4）+ 高密度，取 par 最高者保证是章内最难（ch4 大关 par 24）。

**踩坑**：① 全车可转使状态空间爆炸（生成超时）→ 收窄为仅英雄可转；② 7×7 空间大反而更松（boss par 掉到 3）→ 改为"取 par 最高者"+ 高密度；③ tryMove 初版只认滑动目标，静默拒绝所有转向指令 → 交叉验证抓到。

**验证**：19 单测 + validate(60) + Python 50 关自动通关 ALL PASS + 零页面错误。

## v0.7 第 1 章曲线修复（玩家共创三轮）

**用户试玩原话**："为了保持一致，最好在前 10 关就要接人，但可以简单一点，人就在路边不用专程去接。第十关怎么没法掉头？……主要是前十关太简单了，第十关我不知道怎么解。……只要抬高 1~9 关难度就可以，一二章大关 7×7 就行了。"

**根因**：第 1 章曲线断裂——1-9 关 par 2-3 过于 trivial，第 10 关 7×7 par13 成悬崖；且 boss 写死 turn:false 导致大关不能掉头。

**改动**：
1. **前 10 关加"路边接人"**：乘客放在出口行旁，红车顺路接到、不专程绕（easyPickup），保持简单又统一"接人开闸"语义。
2. **抬高 1-9 关**：ch1 密度/竖挡/墙上调，par 升到 3-5，不再 trivial。
3. **大关开掉头**：bossCfg turn:true，第 10 关可掉头（修玩家卡点）。
4. 一二章大关保持 7×7（按用户指示），曲线平滑后 7×7 成为可达的高潮而非墙。

**结果**：ch1 [3-5]+大关14 → ch5 [8-16]+大关25，递进成立且无断崖。
**验证**：19 单测 + validate(60) + Python 50 关自动通关 ALL PASS + 零页面错误。
