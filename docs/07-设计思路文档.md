# 《挪车！师傅》Carpool Lane · 设计思路文档

> 参赛交付件之一。配套：docs/02 深度调研报告、docs/04 技术方案、docs/06 迭代日志、docs/difficulty-curve.svg。
> 一句话：师傅的车被堵死了——顺路捎上乘客、腾挪出一条活路，开出这条窄巷子。

## 一、我们为什么做这个（调研 → 机会）

基于 CrazyGames / Poki / 微信小游戏官方榜 / 4399 的实抓数据（详见 docs/02）：

1. **疏通/挪车是 2026 H1 增量最大的黑马品类**：Arrows 系单月 25M 下载、CrazyGames 全站 #1 是挪车疏通、微信人气榜「挪了下车」飙升；主办方乐信圣文自己的 Arrows Go（23M 下载）也在该赛道——评审最懂这个品类的价值。
2. **玩家最大抱怨 = "太简单 / 50 关后没新意 / 广告过载"**（Google Play、Reddit 实抓）。而 Rush Hour 的难度可以**数学度量**（BFS 最优步数 + 解路径窄度），无人在 H5 休闲端做过"求解器背书的难度系统"——这是结构性白空间。
3. **主办方成功公式**（Vita Mahjong / Tile Explorer / Meowdoku）：经典规则格式 × 爽感 × 银发友好 × IAA。我们照此选品：规则 3 秒上手，35+ 友好。

## 二、核心玩法与微创新

- **底盘**：Rush Hour 滑块疏通（横车横移、竖车竖移，把红车开出右出口）——全球验证的经典。
- **微创新 A｜顺路捎人**：出口道闸锁着，红车必须先滑到乘客格旁"捎上人"才解锁。把"腾出通道"升级为"规划路线"，两个子问题互相纠缠——合成大西瓜式"经典机制碰撞"，无新规则，只有新化学反应。
- **微创新 B｜按序接送**：多乘客带编号须按顺序捎，在 A 之上再叠顺序约束。
- **克制**：原"班车"时序机制经生成器验证接受率 1/201，按砍序砍掉（见迭代日志）——不堆料。

## 三、难度工程（灵魂 = AI 驾驭力证据链）

- **三层独立实现交叉验证**：JS 规则内核（游戏运行时）、JS BFS 求解器（管线）、Python 独立求解器（端到端自动通关）。任何一层口径漂移都会立刻暴露——开发中确实抓到 3 处同源/异源 bug。
- **关卡生产管线**：生成（英雄车最左 + 出口行竖挡骨架 + 密度分章）→ BFS 验证（可解 + 最优步数 par）→ 解路径窄度（同 par 内最优解越少越难）→ 波浪排序（3 升 1 缓 + 章末峰值）→ validate.js CI 门（50 关全量重验 + 章间中位数单调不降）。
- **结果**：50 关 100% 可解、par 与声明一致、难度梯度成立（ch1 par 1-3 → ch4/5 par 5-7，叠加按序接送/墙提升感知难度）。
- **星级**：3★ = 求解器最优步数，2★ = +2 内，1★ = 通关——给非完美玩家留余地。

## 四、留存与手感（照标杆抄作业）

- Duolingo 三支柱：可视化登山路（道路式选关，进度=夜路里程碑）/ 连胜计数 / 每日挑战（10 关池按日期取模）。
- 峰终定律：章末峰值关 + 通关"红车冲出出口 + 粒子 + 合成音效"做强结束时刻。
- PNAS streak-end rule：高难关后必跟缓冲关。
- 损失厌恶：AI 提示每关限 3 次（求解器同源给最优第一步），持有后不敢浪费。
- 变现（文档层面）：IAA-first，仅激励视频位，永不插屏——直接回应品类最大差评源。

## 五、AI Native 工作方式

人负责设计决策与验证门（G1/G2 试玩、砍刀决策），AI 负责实现与数据。全程"做→测→改"留痕（docs/06）。多模型分工：GLM-5.3 主力开发 / 交叉评审与视觉自审另设会话。评审四维（玩法设计·关卡体验·AI 驾驭力·迭代打磨）均有硬证据对应。

## 六、已知边界与后续

- 难度上限受 6×6 状态空间约束（par ≤ ~8）；若做长线，可上 7×7 + 更强构造器。
- 美术为程序化矢量 + emoji，评审不看美术，故未投入。
- 真机手感已用 Playwright 模拟 + 像素采样验证；建议交付前补一轮真人试玩。
